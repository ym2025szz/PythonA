# PythonA 0.5.0 内测：使用体验优化与验收

本轮实现已进入可安装内测包。目标设备为小米 M367FC，ARM64，Android 17 / API 37。
PythonA 直接运行内置官方 dsh，不需要 DSHA；Provider 和 Key 沿用既有原生存储。

## 已实现

- **浅色代码建议**：本地/Jedi 与 AI 建议都先显示为编辑器装饰，不写入文档；Tab 或触控“接受”后才修改，一次撤销恢复。Esc 忽略、Enter 换行，片段占位符保留 Tab 优先级。中文组合输入、光标/文件/模型变化与服务重启会使旧建议失效。
- **AI 续写**：默认停顿 800ms 后请求；这是触发延迟，不是结果速度。官方路线使用 `ctx.llm.stream()`，没有 Agent、会话或工具执行。兼容路线明确使用其原生 HTTP 适配器，不自动替换 Provider。每次只发送当前文件前 6KiB、后 2KiB，最多返回 8 行、2KiB、256 token；单请求、3 秒间隔、12 次/分钟、30 秒期限。支持独立补全模型、上传总开关、失败冷却与认证暂停。
- **多文件编辑**：各标签独立保留内容、光标、滚动、未保存状态和撤销历史，切换不强制保存；保存全部、关闭确认、持久保存失败提示和原生草稿恢复均已接入。草稿与正式文件分离，外部 revision/hash 变化会形成冲突，可查看差异。
- **模型选择**：输入框附近保留一个模型按钮；搜索、分组、近期模型、真实推理选项及 Provider 管理集中在弹窗。长名称可完整查看，触控打开不自动聚焦搜索框。
- **连续会话**：同一 conversation 使用官方 ACP `new → close → resume`；每轮使用新 MCP 凭据。支持历史分页、标题修改、归档与恢复、输入草稿和中断恢复。历史补丁只读，旧批准不能复活。模型请求结束并完成保存后才释放会话。
- **日常操作**：普通 Run/Tests 使用独立确认窗口；`input()` 保留空行与首尾空格。Tests 支持折叠、筛选、失败优先、单例重跑和精确跳转。文件菜单、长按/右键/键盘导航、可调整底部面板、代码输入工具条、深浅主题、统一 SVG 图标和服务状态入口已整合。
- **可靠性**：补全、聊天、Runtime/Test、Language 的请求与取消状态分离；处理取消早于排队请求、服务通道崩溃、进程 generation 变化和迟到结果。空白/尚未载入文件的编辑器不接收代码输入。

界面参考 [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/SKILL.md) 的交互与信息层级原则，没有引入新的前端框架或运行时依赖。

## 使用方式

1. 输入 Python 时先看浅色建议，按 Tab 或点“接受”；按 Esc 或点“忽略”取消。
2. 工具条“AI 设置”可关闭自动请求，或选择独立补全模型。关闭代码上传会同时关闭 AI 补全。
3. 点击 DSH 输入框上方的模型名称切换模型；正在运行的请求保持原模型。
4. DSH 顶部历史按钮打开会话列表，＋创建新会话；归档不等于删除官方日志。
5. 自动保存关闭时可以自由切换多个未保存文件；编辑器更多菜单提供“保存全部”。
6. Tests 中选择“失败与异常”，可展开 traceback、跳到源码或单独重跑。

## M367FC 真机证据

本轮使用用户已配置的自定义接口和 `deepseek/deepseek-v4.1-flash`。Key 没有写入源码、APK、截图或报告。

- 真实 AI 返回 `a + b`；自动预览时文档仍为 `return `。接受后出现 `return a + b`，一次撤销还原，正式文件没有被提前保存。
- 第一轮约定测试暗号，第二轮准确返回；重启应用后第三轮仍能返回。另一个独立会话回答 `UNKNOWN`，没有串入前一会话的内容。
- 会话重命名、归档、恢复及跨工作区读取拒绝通过。
- 两个文件分别保留未保存内容，磁盘仍为原版本；重新安装/启动后草稿恢复。
- 草稿期间模拟外部修改，重启后保留本地与磁盘两份内容，并可查看双方差异。
- 普通 Run 的确认没有打开 DSH。目标 CPython 中 `input()` 得到 `["", "  kept spaces  "]`，进程 exit 0，结束后输入控件禁用。
- pytest 实际结果 1 通过、1 失败、1 跳过；筛选只显示失败项，定位到第 5 行，单例重跑只收集 1 项。
- 目标 CPython 3.14.7 的 19 项原生通道回归全部通过：输入身份、Unicode、stderr 分离、空测试、收集失败、环境恢复、路径穿越、运行互斥、旧取消拒绝、取消后再运行，以及 Unicode 引用、重命名和整批冲突拒绝。12 个临时回归文件已删除。
- 真实讯飞输入法提交“你好”正确，测试场景中没有误接受补全；浏览器另覆盖了组合输入事件、片段 Tab 和快捷键。未把这些测试宣称为所有实体键盘及输入法型号的完整兼容结论。
- 强制结束正在输出的 `:dsh` 后，界面释放任务并保留中断历史，编辑器继续工作。恢复后真实请求返回 `RECOVERED`。

网络曾临时不可用：当时平板连普通域名也无法解析。用户恢复网络后，真实调用验证通过；没有修改用户的网络设置或 Provider 配置。

这些功能是在本轮多个候选构建上逐步复验的；最终包另外核对签名、安装、哈希和状态。原始脚本与结果位于开发目录 `.runtime-cache/device-acceptance/ux-*`，不混同桌面测试与设备结论。

## 性能观察与限制

- 最后一组共 62 个编辑输入事务样本，事务到下一帧 p95 为 **8.4ms**、最大 13.9ms。Android 注入输入不一定产生 `beforeinput`，因此同时记录 CodeMirror 输入事务；它不是物理按键到屏幕的完整延迟。
- 本地补全观察样本 177.1ms；AI 请求样本 3471.6ms，含 800ms 停顿的界面观察约 4303.8ms。样本数量不足以作为稳定网络性能承诺。
- 本次启动测到 Runtime ready 4330.3ms、WebView 初始化 4727.8ms、模型目录 4748.3ms、Language ready 5562.3ms。这些从 WebView 会话计时，且运行包已安装，不是系统全链路冷启动。
- 当前小工作区索引观察为 23.1ms，不能代替 500 文件基线。
- 普通 Run 取消约 32ms、测试取消约 337ms。
- DSH 强杀试验首次 20 秒探测未就绪，约 20.4 秒重新绑定服务、26.3 秒恢复官方运行时。该延迟仍需后续优化，没有隐瞒为瞬时重连。
- 本轮一次应用 UID 范围的 PSS 观察：Main 415173、Runtime 67345、Language 83167、DSH host 26171、proot 1268、Node 128696 KiB。不包含隔离/共享 WebView 渲染器，不能称完整应用总内存，也不能据单次采样断言无泄漏。

API 30、特定实体外接键盘映射、较旧 WebView、多小时压力和同设备 0.3 性能对比仍未完成；不宣称达到 20% 回归门槛或完整发布验收。生产签名、公开发布及完整发布许可证审计不在本轮交付内。
